# 订阅和插件更新

订阅更新默认关闭，可选择每 6、12、24 小时更新全部 URL 配置。后台计划不依赖 QAM 面板；休眠恢复后只补一次到期更新。下载、规则解析与候选配置检查失败时保留原配置。更新正在运行的活动配置会重启一次 Mihomo；其他配置更新不重启当前代理。手动添加的远程规则集随其所属订阅刷新，原规则顺序不改变。

v0.1 仅保存节点，无法从本地恢复曾被丢弃的原规则。升级后应刷新 URL 订阅，或重新导入完整 YAML。v0.2.1 可直接选择下载、文档或桌面中的 YAML 文件；文件配置没有远程订阅地址，需要更新时重新导入。未刷新前继续沿用旧节点和内置规则。

## 插件更新流程

自动检查默认开启，每 6 小时检查一次；自动安装默认关闭。启用“停止代理后自动安装”表示同意在发现新版且代理停止时短暂重启 Decky。运行中的代理不会被插件更新停止。

发行清单来自固定仓库的 `releases/latest/download/update.json`，签名为 `update.json.sig`。只接受当前内置 Ed25519 公钥、`deckyproxy-update` 命名空间、固定仓库发行 URL 和更高的三段版本号。第三方镜像只能传输公开发行文件，不能改变签名/哈希所认证的内容；个人订阅与规则集不经过这些发行镜像。

安装前完成清单验签、大小和 SHA256 检查、ZIP 安全检查及内核哈希检查。候选目录和旧插件通过 Linux 原子目录交换切换，独立 systemd helper 在 Decky 重启期间继续执行。新后端写入本次随机事务标识及版本的健康标记；未及时确认则恢复旧目录并重启 Decky。个人 settings 位于插件目录之外，不参与替换。

这只验证后端加载成功，不代表完成 Steam Deck 实机网络验收；首次升级仍应检查订阅、节点切换、TUN、休眠唤醒及停止后的联网恢复。安装期间不要卸载插件或清理 settings/backend/updates。

## 发行签名

先完成测试、`scripts/package.py`、`verify_release.py` 和脱敏检查。发行者使用仓库外、权限为 0600 的 Ed25519 私钥执行 `scripts/sign_release.py --key <私钥文件>`，脚本签名并用仓库内公钥立即验证。私钥不能进入 Git、安装 ZIP、源码包或 CI 日志。

将版本 ZIP、对应源码、SHA256SUMS、update.json 和 update.json.sig 一起上传至同次 GitHub Release。自动更新频道使用 GitHub latest，因此发行必须明确设置为 latest；未经 Steam Deck 验收的状态应在说明中如实标注。更换发行公钥需要先用旧公钥签署包含新信任配置的过渡版本。
