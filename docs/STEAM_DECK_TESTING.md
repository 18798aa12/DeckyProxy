## 安装与基本操作

- [ ] 核对 `SHA256SUMS`，从 Decky 的开发者 ZIP 安装入口安装。
- [ ] 初次打开时代理与自动启动关闭；仅导入不会改变网络。
- [ ] 手柄方向键、A / B、屏幕键盘能完成名称和 URL 输入、节点选择与返回。
- [ ] 没有配置时不能启动；错误订阅有清晰反馈。
- [ ] 导入一个公网 HTTPS Clash YAML，界面只显示来源主机而不回显订阅令牌。
- [ ] 粘贴 YAML 可导入；有 HTTPS provider 的订阅可展开。
- [ ] 从下载、文档或桌面目录选择 `.yaml` / `.yml` 并导入；取消选择保留输入，导入后移走原文件仍能启动。
- [ ] 文件选择器打开而快捷菜单隐藏时，选择文件仍发出一次导入请求；返回后按钮旁显示结果，新配置被选中。失败后等待状态轮询，错误仍保留且可重试。
- [ ] 输入和屏幕键盘中按 B 结束编辑且草稿保留；主页面第一次 B 保持页面，2 秒内第二次 B 返回 Decky；长按 B 不直接退出。
- [ ] 在配置区和长策略组列表中验证 B 提示保持可见，第二次 B 确实返回插件列表；输入框自动恢复焦点时不会重复吞掉 B。关闭快捷菜单后，Steam 的返回不受插件影响。
- [ ] HTTP、`file://`、回环/私网下载目标、错误 YAML、超大内容、重复节点及循环/过量展开的 YAML 别名被明确拒绝；普通锚点与合并可导入。
- [ ] 完整订阅的策略组、规则顺序及 RULE-SET 引用保持，HTTP/inline 与 YAML/text/MRS 规则集可加载且数量非零。
- [ ] 验证 AnyTLS、WireGuard、链式拨号的实际连接；IP-ASN/SRC-IP-ASN 离线数据可加载，规则集格式修正提示符合导入结果。
- [ ] 向当前配置添加规则集，刷新订阅后仍保留；旧版配置刷新一次后恢复订阅原始规则。

## 网络与模式

- [ ] TUN 关闭时，只有应用显式设置 `127.0.0.1:19790` 才经过代理；不能把内核运行状态等同于系统已接管。
- [ ] v0.2.3 开启 TUN 后不再误报“路由未建立”；策略组和节点可见，停止后专用接口、路由及策略规则清理；重复启停没有冲突。
- [ ] 策略组与节点默认折叠；鼠标点击或手柄 A 可展开总列表，再单独展开策略组选择节点或测速；收起后焦点停在对应按钮，状态轮询不会自动展开，切换配置或停止代理后重新折叠。
- [ ] 开启 TUN 后测试 Steam 商店网页、一个普通 HTTPS 网站及 DNS 解析。
- [ ] 使用支持 UDP 的节点验证一个游戏的实际联网，记录连通性与延迟，不以网页延迟替代游戏延迟。
- [ ] 规则模式：完整订阅按照原规则匹配；节点订阅使用局域网直连的内置规则。含 GEOIP/GEOSITE 的订阅在首次启动离线加载数据库。
- [ ] 全局模式选择 GLOBAL 策略后生效；直连模式和“停止代理”分别检查。
- [ ] 切换节点、自动选择、模式和 TUN 后界面与实际流量一致。
- [ ] 验证 Steam 下载是否使用代理，避免在未知计费情况下长时间下载。
- [ ] 分别测试 Wi-Fi 与 USB / 扩展坞网络、连接切换、掉线重连、睡眠与唤醒。
- [ ] 检查 IPv6 网络行为；当前未提供 IPv6 代理承诺，不能宣称无泄漏。
- [ ] 使用手机或其他局域网设备确认无法访问 Deck 的代理与控制器端口。
- [ ] 确认设置位于 `DECKY_PLUGIN_SETTINGS_DIR/settings.json`，订阅和节点位于其 `profiles/*.json`，含 secret 的运行文件位于其 `backend/`；检查可被 Decky 静态 HTTP 读取的 runtime 目录没有私密文件。

## 退出与错误处理

- [ ] 开启后正常停止：本插件内核退出，TUN 和专用路由清理，直连 DNS 和网页恢复。
- [ ] 连续重复启停，确保没有多个内核或遗留 TUN。
- [ ] 运行中切换/更新配置，成功时生效；订阅失败保持已有配置。
- [ ] 无法启动的节点配置、占用的端口和权限不足会报错，不无限重试。
- [ ] 重载插件、正常卸载后没有本插件子进程，直连恢复。
- [ ] 在有现场操作能力时测试 Decky Python 后端异常退出，确认父进程退出保护可让内核退出。
- [ ] 仅对本插件的进程做故障注入；不能使用 `pkill mihomo` 去停止其他客户端。
- [ ] 重启 Steam Deck；自动启动默认关闭时保持直连。单独验证用户主动开启自动启动后的行为。
- [ ] 运行期间与停止后对比 `/etc/resolv.conf`、NetworkManager 配置，确认插件未改写系统 DNS 文件。

## 自动更新

- [ ] 订阅周期设置在重启后保留；关闭面板仍刷新，到期下载失败保持旧配置，休眠恢复不重复补跑。
- [ ] 自动检查默认开启、自动安装默认关闭；检查更新不重启 Decky。
- [ ] 开启自动安装后，运行代理时等待；代理停止后才准备并安装，个人配置完整保留。
- [ ] 下载期间重新开启代理，或关闭自动安装时，不进入安装与 Decky 重启。
- [ ] 验证错误签名、下载中断、磁盘不足时旧插件可继续使用；新版后端无法初始化时自动回滚。
- [ ] 确认短暂重启 Decky 后界面版本与后端一致，节点选择、规则、订阅周期与开关仍在。
- [ ] 在可现场恢复的测试环境验证独立 systemd 更新助手跨 Decky 重启存活；断电恢复只能在备份后进行。

## 网络异常时

1. 能进入 Decky 时关闭“启用代理”，关闭自动启动，再检查网络。
2. 同时检查其他代理/VPN 是否仍运行；一个客户端停止后另一个客户端的路由可能仍存在。
3. Decky 不可用时重启 Steam Deck，保持本插件自动启动关闭，再检查直连。
4. 仍异常时切换到桌面模式，检查网络连接、设备当前 DNS 和其他 VPN 状态，保存脱敏错误信息。不要直接套用其他插件的系统 DNS 重置命令。

本插件不备份/恢复系统 DNS，因为它不应修改那些文件。不要删除整个 Decky settings 目录。需要重新初始化个人配置时，先停止插件，将**本插件**的 settings 目录改名备份，再重新加载；保存的订阅会暂时离开插件，备份中仍含凭据。

建议问题报告包含版本、操作步骤、模式、TUN 状态、是否存在其他代理与脱敏错误；不要附订阅 URL、节点密码、token 或完整 settings 文件。
